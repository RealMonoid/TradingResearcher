# Public targets and exact private bindings — October 26, 2026

## Purpose and system boundary

The prior development data-use checkpoint could not support formalization for a protected period without an exact target reference. Supplying a protected snapshot or its derived definition identity to the model would expose information outside the intended context. The investigation therefore asked whether a predeclared public contract could be resolved privately without changing the claim, feature meaning or candidate knowledge. A dependence of public packets on private values, coverage or binding success would invalidate that design.

The [retail contract](../../architecture/14_RETAIL_RESEARCH_CONTRACT.md) sections 1, 4, 6, 8, 12 and 14 govern scope, typed formalization, calendar partitions, immutable versions, fixed releases and implementation certification. This is infrastructure for those existing semantics, not a new scientific rule or approval of historical data as unseen. Unknown external selection knowledge and model training remain unknown. No canonical scientific decision or estimator expectation changed.

The system still separates freely proposed H_idea, faithful H_exec, independent deterministic evaluation and retained feedback. The new normal path is: operator declares scope from certified development semantics; formalizer receives that immutable public reference; a separate reviewer receives the original declaration and exact public definitions; host compilation consumes an explicitly supplied private exact binding. The candidate is not rewritten. Compilation retains the private technical ancestry and grants no scientific result. Protected scientific data/exposure admission, calibrated inference/information, atomic family allocation/freeze and controlled fixed release must still precede protected execution.

On a failed binding, an immutable private gap is retained while the original public declaration and model packets remain unchanged. On an invalid or unsupported candidate, the existing retained-gap path remains available. Arbitrary text in such a gap cannot cause an existence/schema lookup outside its original authorized references. Neither failure path gives a model access to private outcomes or restores freshness to exposed history.

## Implemented behavior

The [runtime contract](../../../trading_researcher/DATA_TARGETS.md) documents the operator RPCs, new `research-data-target/1` and `protected-data-binding/1` records, exact idempotency and optional compilation argument. A declaration does not search for protected data and can precede its acquisition. The private binding checks exact snapshot/certificate identity, calendar containment, full feature definitions, parameters, specification versions and actual normalization delay. It is never selected implicitly as a latest mapping. Workers cannot create or resolve these records themselves.

Independent meaning review requires the original public target in its explicit context and packet, including when a candidate proposes different dates. The host checks the public-to-private definition mapping separately. Existing direct-snapshot behavior and retained numerical calculator functions remain intact. Private bindings and descendants are denied to discovery/formalizer contexts; current technical revocation follows actual dependencies and retains historical bytes. Database/blob backup and restore preserve the new identities.
