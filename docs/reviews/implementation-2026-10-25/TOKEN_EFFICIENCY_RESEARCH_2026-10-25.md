# Token efficiency without weakening research

Research date: October 25, 2026. Scope: the current provider loop, frozen research budgets, source presentation and usage accounting. This is an implementation investigation, not a scientific-contract amendment or a claim of unchanged LLM quality.

The user requested economical token use while explicitly preserving research quality and the backtest. The uncertainty is whether savings come from cheaper processing of identical input, reversible encoding, or withholding information. These have different validation requirements. A cheaper price does not enlarge the adopted 80,000-token epoch budget.

## Observed bottleneck

The retained real-data count-only request contains 43,730 input tokens and 87,405 serialized wire bytes. Two initial perspectives alone would require 87,460 input tokens, before any output or later call. The count endpoint performed no inference; it is not additional consumed inference usage. The four earlier synthetic integration calls consumed 2,172 reported tokens and had a conservative USD 0.006435 cost bound, not representative research consumption.

The large source envelope includes 607 exposure IDs and 96 entries each in raw-source references, checksum references and archive URLs. These lists remain evidence: the URLs carry date, symbol and archive-variant detail. They cannot simply be called irrelevant overhead. Coverage, availability assumptions, rights, transformations, scientific gates and the 18-feature catalog must remain visible.

The implemented opt-in view was subsequently counted through the same endpoint and owned controller path: **3,456 initial input tokens**, including the added section tool, versus **43,730**. The saving is **40,274 initial tokens (about 92.1%)**. Instructions, purpose, model configuration and original source IDs were held fixed. Exact local reconstruction of all deferred lists passed. Neither count dispatched inference; the paid ledger remained byte-identical. The [observation](context-efficiency-observation.json) retains requested model/catalog version, explicit unknown immutable model snapshot, UTC count time, full proposed request and transport request ID. This measures an initial input, not an entire research epoch or research-quality equivalence.

## Findings and disposition

| Mechanism and primary source | What changes | Application here |
|---|---|---|
| [OpenAI prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching) | Reuses computed state for an identical rendered prefix; generates a fresh response. Cached input still occupies context and counts toward token limits. | Preferred cost mechanism. Keep existing stable tools/messages. Current supported models enable implicit caching by default; do not silently reorder perspective instructions. Cache writes can have their own rate, so a hit percentage alone is not a cost calculation. |
| [Exact input counting](https://developers.openai.com/api/docs/guides/token-counting) and [tiktoken](https://github.com/openai/tiktoken) | Counts or estimates input; does not compress it. | Continue the adapter's exact endpoint preflight. A local tokenizer is useful for estimates only after verifying the exact model encoding and message/tool overhead. No additional installation is necessary now. |
| Deterministic source views and exact list sections | Changes which provenance entries are initially presented, retaining every original byte locally and bounded access to ordered entries. | Implement as explicit, versioned opt-in infrastructure. Preserve every other source field and all controller exposure. Measure actual counts; do not infer equal research quality from retrievability. |
| [OpenAI Batch API](https://developers.openai.com/api/docs/guides/batch) | Discounts independent asynchronous requests, with up to a 24-hour completion window. | Candidate for independent offline evaluations or reports later. It does not fit the current 30-minute interactive research epoch and dependent tool loop without a separately reviewed workflow change. |
| [OpenAI tool search](https://developers.openai.com/api/docs/guides/tools-tool-search) and [Claude tool-context management](https://platform.claude.com/docs/en/agents-and-tools/tool-use/manage-tool-context) | Defers tool definitions or changes tool execution/context. | Defer: the framework has a small fixed tool set. Dynamic tool availability must never enlarge frozen permissions. No arbitrary model-authored code execution is introduced to save round trips. |
| [Claude prompt caching](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-use-with-prompt-caching) and [Gemini optimization](https://ai.google.dev/gemini-api/docs/optimization?hl=en) | Provider-specific reuse and billing of stable context. | Relevant to later adapters. Do not assume cache fields, storage/TTL pricing or token semantics transfer unchanged between vendors. |
| [TOON](https://github.com/toon-format/toon/tree/e247c423e0a38bca3477b17fecdf6ef4feeb5584) | Reversible JSON-oriented text serialization, strongest for uniform tables. | Candidate only after exact round-trip and model-specific token measurements against our already compact canonical JSON. Published comparisons with pretty JSON are not our baseline; nested envelopes and long hashes may gain little. Keep canonical stored artifacts unchanged. No installation adopted. |
| [LLMLingua-2 paper](https://aclanthology.org/2024.findings-acl.57/) and [Microsoft implementation](https://github.com/microsoft/LLMLingua) | A learned token classifier selects/removes text; evaluated compression results are task/model dependent. | Do not apply automatically to research constraints, source evidence, missingness or exposure. Those benchmarks do not establish lossless preservation of our scientific meaning. No installation adopted. |
| [OpenAI compaction](https://developers.openai.com/api/docs/guides/compaction) | Replaces prior context with a compact representation. | Not an automatic substitute for exact research memory. Any behavioral savings require separate evaluation. |
| [Conversation state](https://developers.openai.com/api/docs/guides/conversation-state) | Server-side continuity can simplify request construction. | A previous-response identifier does not make earlier input tokens free. Preserve the current auditable transcript and explicit accounting. |

The [OpenAI Cookbook caching notebook](https://github.com/openai/openai-cookbook/blob/main/examples/Prompt_Caching_201.ipynb) explicitly limits its advice to models before GPT-5.6. Its older no-cache-write-fee description must not override current model-specific documentation. The inspected notebook blob was `b1414bc82b482bf9d51baadb34806b82810a8541`; the inspected TOON commit was `e247c423e0a38bca3477b17fecdf6ef4feeb5584` (October 9, 2026).

The academic study [Lost in the Middle](https://aclanthology.org/2024.tacl-1.9/) found position-dependent retrieval performance in its evaluated models/tasks. It motivates testing context presentation rather than equating more supplied text with better use. It does not prove that a compact view improves our current model or market research.

## Implementation and quality boundary

The smallest coherent change is `discovery-source-view/1`: defer only large arrays at five fixed reference/provenance paths, show their exact counts and canonical hashes, and expose an authenticated ordered slice tool. No ranking, semantic summary, source removal, URL following or widening of read permissions is involved. The full source-read tool remains available. Legacy profiles remain unchanged; new profiles explicitly freeze the presentation version and tool definition.

Full reads and accumulated sections can still exhaust the original input/call/token budgets. An inability to read needed material must remain an access/resource gap. Restoring an array byte for byte proves data preservation, not that the model notices or requests every needed entry. This capability therefore remains opt-in and is not a verified quality-equivalent default for scientific discovery.

Backtest calculations, raw bars, horizons, units, precision, missingness, realistic costs, frozen evidence rules and independent perspectives are outside the change. Reusing a cached LLM answer is not an independent perspective. Smaller models, reduced reasoning, tighter output truncation, history deletion, reduced data coverage and coarser backtests are not adopted as savings measures.

Verification must cover unchanged nondeferred fields, ordered reconstruction including duplicates, authentication before path inspection, bounded results, original inherited exposure, legacy payload equivalence and unchanged calculator source hashes. Token-count observations must retain model/version and UTC observation time separately from paid usage. Before any quality-equivalence claim, evaluate representative source/qualification access and actual research behavior under the same frozen budgets; a single smoke test cannot establish it.

Conclusion: identical-prefix caching is the strongest immediate cost mechanism; exact on-demand provenance is a measurable context-saving candidate with explicit behavioral limits. No new service or compression package is required for this slice. Implementation outcomes and unverified boundaries are recorded separately in the [verification record](context-efficiency-verification.json).
