## Outcome and inspected starting point

The first milestone is one bounded, traceable historical research cycle: a real LLM invents an idea, the application preserves its meaning, independent code evaluates a supported formalization under a frozen plan, and the journal retains the entire batch and its outcomes. A negative or inconclusive result can complete the technical milestone. Unsupported ideas remain gaps and do not count as tested negatives.

The inspected repository is at commit `0db94668bb315c23ed824246abf0c0b02cf668f6`. It contains a [local controller](../../../trading_researcher/README.md) and a bounded [AmiBroker utility](../../../tools/amibroker/README.md). The controller handles operational jobs and immutable artifacts; it does not yet implement scientific freeze, the researcher, four complete memory views, or the evaluator. AmiBroker has a recorded import/exploration/export test, not a certified strategy adapter. The [system reconstruction](SYSTEM_MODEL.md) remains the flow and authority basis; its earlier inspection commit describes its historical snapshot.

Use the existing Python application and SQLite registry. Start with direct provider calls behind one owned interface, deterministic reference calculations, and explicit metadata/text retrieval. A new agent platform, graph database, vector database, or dashboard is not a prerequisite. The accepted [research contract](../../architecture/14_RETAIL_RESEARCH_CONTRACT.md), [decision register](../../architecture/02_DECISION_REGISTER.md), and [blueprint](../../architecture/09_IMPLEMENTATION_BLUEPRINT.md) govern meaning and authority.
