# Public archive acquisition and exact normalization

This adapter acquires the adopted BTCUSDT/ETHUSDT spot 15-minute monthly archives for 2020-2025 under [research-contract/1.0 section 6](../docs/architecture/14_RETAIL_RESEARCH_CONTRACT.md#6-open-06-data-and-execution-authority). Successful acquisitions preserve original ZIP, checksum and CSV bytes with their hashes, request URL, HTTP metadata and separate start/retrieval times. New acquisitions record each file hash immediately after saving that file, before further checks; failed attempts preserve those completed hashes and available bytes. Legacy failure receipts with an empty manifest remain explicitly unbound to their files. Acquisition, normalization, historical availability and scientific acceptance remain separate questions.

The [official archive documentation](https://github.com/binance/binance-public-data) defines the kline columns, the switch to microseconds for spot files from January 2025, accompanying checksum files and possible later corrections. Earlier files use milliseconds in this adapter's declared profile. A present download does not authenticate an earlier vintage. The [dataset terms](https://github.com/binance/binance-public-data/blob/master/TERMS_AND_CONDITIONS.md), checked October 25, 2026, describe personal non-production historical research among permitted non-commercial uses and restrict live/commercial use. `capture_provider_docs` retains exact acquisition-time README and terms bytes. These source documents and qualified rights metadata must travel with later data records; this adapter does not approve deployment or redistribution.

Run from the repository root:

```powershell
python -B -m trading_researcher acquire-binance-month --symbol BTCUSDT --month 2020-01 --directory .trf-runtime/binance/BTCUSDT-2020-01
python -B -m trading_researcher inspect-binance-month --directory .trf-runtime/binance/BTCUSDT-2020-01
```

These directories contain source acquisitions, not SQLite registries. Each acquisition requires a new directory and never overwrites an earlier attempt. Failed downloads, checksum rejection or parsing leave available source files and a failure receipt. Reuse verifies all exact files, the checksum, archive contents, parsed coverage and qualified receipt fields without a network call or refreshed retrieval time. A local administrator can still rewrite an entire receipt and its inputs; this is integrity checking within the trusted-host boundary, not a signed provenance system.

Monthly acquisition requests only the constructed HTTPS archive URL and its checksum URL; provider-document capture uses the two fixed README/terms URLs. Redirects and environment proxies are disabled. Each request runs in an owned child with a parent-enforced 125-second lifetime; cancellation or timeout kills and reaps that child. Transport checks a 120-second success deadline around bounded reads, including EOF, and uses a 30-second socket timeout. There is no automatic retry. Responses are bounded to 8 MiB per ZIP, 4 KiB per checksum and 16 MiB uncompressed CSV. Provider-document captures are bounded to 1 MiB per file. These are software limits, not an assessment stopping policy.

The ZIP must contain one exact expected CSV member. Checksum filename/content mismatch, extra or duplicate members, traversal names, unsupported/encrypted content, decompression errors and CRC failure are rejected. The reader never extracts archive paths to disk. CSV uses strict UTF-8 and twelve columns; malformed quoting and multiline numeric fields are rejected rather than repaired. Source decimal values remain exact and ordinary, with only trailing fractional zeroes removed. There is no binary-float conversion, implicit rounding or replacement of missing rows.

Each source open must be on its declared 900-second grid and within the named month. The inclusive close tick must equal `open_raw + 900 * factor - 1`; duplicates and reversed opens fail. Parsed `end_time` is the exact exclusive boundary 900 seconds after `open_time`. OHLC prices must be positive and ordered; volumes are nonnegative and taker quantities cannot exceed their totals. Trade counts are nonnegative integers. Missing grid bars are retained as explicit coverage gaps. A valid zero-activity bar remains present. The parser does not reconstruct trades or add an unsupported tolerance for quote/base rounding identities.

Real archives can contain maintenance gaps or irregular close timestamps. A matching provider checksum does not make such a bar compatible with the complete-bar specification. Strict normalization retains a failed month and its original bytes rather than silently changing its timestamp or selecting a convenient replacement. The official project's [issue 77](https://github.com/binance/binance-public-data/issues/77) documents related irregularities; a local failure is established by its retained bytes, not by that discussion alone. The separate keyed quality audit below preserves these observations without changing the strict parser's acceptance rules.

`reference_rows(parsed, delay_seconds=...)` constructs a separate, explicitly chosen availability scenario. The delay has no default. Row time is the exclusive bar end; availability is `end_time + delay_seconds`, labeled assumed, with historical publication unknown and scientific readiness false. It retains all boundary rows, including ends at the next month/year. Partition selection must account for these explicitly; this function does not relabel them or silently drop them.

Feature identifiers are symbol-qualified and versioned, such as `BTCUSDT.close@binance-spot-15m-v1`. BTC prices use `USDT/BTC`, base volumes `BTC`; ETH prices use `USDT/ETH`, base volumes `ETH`. Quote volumes use `USDT` and counts use `count`. This prevents unlike asset quantities from sharing a unit identity. It neither adds compound-unit algebra to the reference engine nor certifies an inferential feature. Later shared return features need explicit compatible definitions and independent checks.

[Forty-three independently authored cases](../tests/fixtures/reference_binance_cases.json) cover exact ms/us timing, decimal precision, gaps, close/partition boundaries, quantity invariants, checksums, ZIP errors and explicit delay assumptions. Their [expectations note](../tests/fixtures/reference_binance_expectations.md) predates implementation inspection. Additional tests exercise receipts, corrupt cache reuse, malformed multiline CSV and real child cleanup. Passing these checks establishes the bounded adapter behavior; feature certification, accepted data manifests, frozen scientific execution, statistical calibration and market conclusions remain separate work.

## Keyed quality audit and registry retention

`binance_quality.audit_month(raw, symbol, month)` requires unambiguous, aligned, unique increasing source opens. Unknown layout, broken quoting, multiline records, invalid keys or reversed/duplicate keys reject the whole source. For a keyed record, an invalid close, trade count, quantity or OHLC/volume invariant instead produces `INVALID_BAR`, a typed reason and no usable bar values. Every record binds its physical line number and exact raw-line SHA-256, including the original line ending; the audit binds the full CSV hash. The retained original CSV contains rejected field values. The first failing bar check supplies the reason; the record does not claim an exhaustive list of defects.

Coverage reports expected, present, valid, invalid and absent counts separately. Valid plus invalid equals present; present plus absent equals expected. Missing bars remain absent. For an invalid close, `end_time = open_time + 900` denotes only the expected grid boundary, never an observed or repaired close. The strict parser still rejects such input, and an earlier acquisition failure receipt stays a failure.

`quality_reference_rows(raw, symbol, month, delay_seconds=...)` re-audits raw bytes and constructs an explicit assumed-availability scenario. Invalid keyed observations become rows with all nine feature values null. Valid zero-activity bars retain genuine zeroes. No missing row is filled. The delay has no default and does not establish historical publication. Boundary rows remain present for later explicit partition handling. This representation does not authorize ignoring defective observations in an estimator: the frozen scientific missingness/eligibility policy and feature/data certification remain separate.

Retain existing acquisitions in an owned registry with:

```powershell
python -B -m trading_researcher retain-binance-month --directory .trf-runtime/research --source-directory .trf-runtime/binance/BTCUSDT-2020-01
python -B -m trading_researcher retain-binance-docs --directory .trf-runtime/research --source-directory .trf-runtime/binance/provider-documents
```

`binance_ingest.retain_acquisition` authenticates the operator, captures and verifies exact ZIP/checksum/CSV/receipt bytes, re-audits them, and imports them through the host's committed blob operation. A complete `row-quality.jsonl` preserves every row's audit. The final `binance-source-bundle/1` binds the files, quality source, coverage and original receipt status with explicit ancestry. Source months before 2024 are development; 2024 and 2025 are protected assessment sources. Callers cannot override that classification. A success receipt is revalidated against the captured bytes; a failed receipt cannot be promoted to success. Missing/corrupt/ambiguous inputs fail before imports. An interruption during multi-file retention can leave committed raw source artifacts; only the final supplied-source bundle describes the complete audited set. Repeated calls append records and do not promise idempotent attempt identity.

A complete failed-file manifest must exactly match the captured bytes. Legacy failures with an empty manifest retain `receipt_file_binding: UNVERIFIED_LEGACY_FAILURE` and `retrieved_at: null`; their old receipt time is preserved separately as `original_receipt_retrieved_at`. The fresh `verified_at` timestamp describes current inspection only. This prevents newly substituted but internally consistent cache files from inheriting an unbound old retrieval claim. A verified receipt/file hash binding still does not prove historical publication or a provider-authenticated vintage. Original failed receipts are never backfilled or rewritten.

`retain_provider_documents` separately binds exact acquisition-time README/terms/receipt bytes and declared URLs. It preserves their provenance and qualified purpose; it grants no deployment or redistribution rights. Monthly source bundles require that separate documentation evidence before later use. Both operations remain within the trusted local host/operator boundary. File hashes and provider checksum agreement do not authenticate a historical vintage or the truth of a supplied receipt. The bundle is a supplied source, not a host-issued scientific certificate; code execution identity, acquisition acceptance and scientific interpretation remain unverified. Large row audits are owned blobs and travel with complete registry backups.

It preserves full receipt validation, exact boundary counts and source ancestry, and emits qualified data snapshots rather than scientific acceptance.
