# Reference implementation certification

This is the bounded IF-04 implementation-conformance gate under [research-contract/1.0 section 14](../docs/architecture/14_RETAIL_RESEARCH_CONTRACT.md#14-open-14-automatic-certification-within-an-approved-envelope). It can certify the exercised reference arithmetic/time/missingness implementation within its existing specification. It cannot certify supplied market features, source availability, natural-language equivalence, uncertainty calibration, scientific evidence or deployment authority. The original idea remains unrestricted; unsupported meaning is still a retained gap.

The operator operation `certify_reference` takes no caller-supplied code, paths, expectations or verdict. It retains the fixed source dependency closure as a host-owned `reference-source-package/1` backed by [immutable blobs](STORAGE.md), then runs a fresh Python child from those captured bytes with isolated imports and no site packages or existing bytecode cache. Pinned specification, independent golden-fixture and supplemental test hashes must match. The validator checks all 112 expression and 31 outcome cases directly, then runs the fixed causality, metamorphic, unit/missingness and resource regressions. Failures, missing dependencies, timeout and source changes produce a retained `CERTIFICATION_GAP`. The controller alone stores an immutable `implementation-certificate/1`; generic source/worker writes cannot mint either namespace.

The certificate binds the exact retained source package, Python executable/version and loaded standard-library files. Imported modules outside that closure are rejected. The parent rechecks both copied and retained snapshots; an installed-snapshot validation also rechecks the workspace footprint before commitment. `reference_certificate_status` resolves a host-issued registry ID, verifies retained package bytes and reports whether the installed snapshot still matches. Changed source, specification, expectations or runtime files make it stale; corrupt/missing retained bytes produce `QUARANTINED`, while legacy records without retained source are `LEGACY_UNBOUND`. It does not certify code already imported into an older long-lived process, nor Broker authentication/issuance, which has separate integration tests. Later scientific execution must use a fresh bound snapshot and verify the frozen certificate before calculation.

Child validation runs outside the registry write transaction so ordinary worker leases can continue. Source publication and final hash/record commitment hold the lock briefly. The source package and an attempt-start event are durable before validation; the final certificate links both. Exclusive-writer startup records an unfinished earlier attempt as `INTERRUPTED`. `inspect_reference_checks` provides a bounded history and pending count. Completed attempts, observed failures and interruptions confer no market conclusion. This records recovery state; it does not automatically retry an interrupted request.

The trusted local operator, installed Python, validator and filesystem remain the trust boundary. This is not an OS sandbox or a defense against an administrator replacing both validation logic and its pinned profile. The expression language exposes no file, network, shell, import or callback operator; fixed tests exercise that capability boundary and numerical resource stops. The child has a bounded wall-clock lifetime. Maximum-dataset memory/performance, hostile native code and arbitrary generated Python are outside this certificate.

`revalidate_reference(source_package_id)` resolves an owned package and checks its retained bytes under the applicable fixed profile without reading the workspace. It emits a new certificate or gap with `validation_mode: retained_package`; successful historical replay is distinct from `CURRENT` installed-version status. Original failed/interrupted attempts remain. Complete backup bundles preserve the code/specification/test bytes needed for replay. Python binaries and standard-library distributions are fingerprinted, not archived; an unavailable/incompatible runtime still blocks replay or requires fresh compatible conformance.

Profile changes must retain prior certificates and expectation provenance. Changed scientific meaning still requires D008/D026 approval. A routine implementation revision may receive a new certificate only after unchanged independently fixed expectations and the profile's other checks pass. Per-feature definition/availability/dependency certification, data manifests, bound scientific execution and complete scientific freeze remain additional requirements.

Run `python -B -m trading_researcher certify-reference --directory <registry-directory>` to create and retain a certificate or gap. Replay with `python -B -m trading_researcher revalidate-reference --directory <registry-directory> --source-package-id <package-id>`. Both commands print the immutable record and exit 0 for `CERTIFIED`, 2 for a retained certification gap. The authenticated `rpc` command also exposes these operations, `reference_certificate_status(certificate_id)` and `inspect_reference_checks(limit)`. They are unavailable to worker capabilities.
