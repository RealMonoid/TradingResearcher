# Public research targets and private data bindings

These authenticated operator RPCs implement a versioned reference resolver within research-contract/1.0. They enable formalization against predeclared protected periods without giving the model protected data or data-derived metadata. They do not grant protected execution, scientific admission, allocation or freeze.

`declare_data_target(key, partition, universe, development_feature_certificate_id)` creates an immutable `research-data-target/1`. The partition is `assessment` or `corroboration`; the explicit UTC universe must fit the adopted calendar and instrument profile. The host verifies existing certified development feature definitions and their explicit delay. The public target contains this declaration, development catalog/definition identities, full-semantics hash and development provenance. It does not search for a protected dataset and contains no protected snapshot/certificate identity, coverage, quality or readiness result. External selection knowledge and model training exposure remain unknown.

The declared target can exist before protected acquisition or certification. Its bytes and model availability do not depend on a later private binding's success. A formalizer may use its ID as the authorized opaque `test_universe.data_snapshot_ref`. Existing direct snapshot references retain their meaning. This new reference schema does not change the candidate's AST, estimand, horizon or outcome semantics.

`bind_data_target(key, target_id, data_snapshot_id, feature_certificate_id)` creates a separate, immutable `protected-data-binding/1` with `TARGET_BOUND` or a retained `TARGET_BINDING_GAP`. This record is private to host/evaluator work. It checks the exact protected snapshot/certificate, declared partition and coverage of the declared window, matching catalogs, and equality of **all** feature definitions, parameters and specification versions. Equal feature names/types/units alone are insufficient. Availability delay must also match each certificate's actual normalization. A binding failure does not rewrite, withdraw or annotate the public target.

Both operations use exact idempotency keys: same key/content returns the retained object; changed content conflicts. Binding records are not mutable lookup slots. The operator supplies `data_target_binding_id` explicitly to `compile_hypothesis` via RPC. The resolver verifies the original target authorization and exact formalized universe, checks current technical dependencies, and binds both public and private identities in the retained compilation. There is no automatic latest binding, implicit rebinding or private-reference selection by a worker. The existing CLI remains the direct-snapshot interface; these new operations and the optional binding argument are available through authenticated operator RPC.

For independent meaning review, the original public target must be an explicit review-context artifact and appears as `data_target` in the review packet. The reviewer also receives exactly the declared development definition identity. The host privately verifies its complete meaning against the target's actual feature definition identity; later plan-review mapping requires the declared public ID. The direct-snapshot path preserves its original strict definition-ID rule. Untrusted references in retained DATA_GAP candidates cannot trigger an internal existence/schema lookup outside their original authorization.

Private bindings and their descendants cannot enter discovery/formalizer contexts, including through source/exposure wrappers. An active worker can read only its frozen authorized artifacts. Compilation carries protected provenance and remains unavailable to discovery/formalization. Technical revocation follows target/development certificate, private binding/protected snapshot/certificate and compiled dependencies. Historical artifacts remain unchanged. Full database/blob backup preserves both declaration and private binding.

The host and local filesystem remain trusted; this is not OS isolation or proof against an operator deliberately encoding private information in public input. Prior knowledge is not erased, and archive partitions are not asserted to be model-unseen. Protected scientific data/exposure admission, outcome eligibility, calibrated inference/information, atomic family allocation/freeze and fixed result release remain separate, unfinished requirements. `execute_development` still rejects protected targets before row expansion. A separately [qualified private plan draft](DATA_USE.md) can now consume the exact binding and declared development diagnostics; it grants no protected execution or data release.
