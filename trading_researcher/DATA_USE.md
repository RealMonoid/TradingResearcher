# Qualified development data use

`assess_data_use(compiled_id)` is an authenticated operator operation implementing the bounded historical-use qualifications in [research-contract/1.0 sections 1, 6 and 12](../docs/architecture/14_RETAIL_RESEARCH_CONTRACT.md). It returns an immutable `data-use-assessment/1`. `inspect_data_use(assessment_id, compiled_id=None)` checks current usability; supplying a different compiled identity is rejected. Workers and generic source records cannot issue these assessments.

The supported positive result is `QUALIFIED_EXPLORATION`, for the exact compiled development hypothesis, snapshot, catalog, feature certificate/definitions, normalization, window, instruments and personal non-production purpose. It is not independent confirmation or protected assessment/corroboration admission. Unknown model training exposure remains unknown, evidence origin remains `null` with a reason, and known target exposure remains visible. An assumed delay is an explicit scenario, not verified historical point-in-time availability.

The host verifies the accepted formalization and exact compiled inputs, retained reference package, independent feature certificate/source replay, source blob integrity, normalization and matching feature availability parameters. It checks exact provider document bytes and receipt bindings. The reviewed Binance dataset terms v1.0, section 4.1, cover personal non-production historical research; the repository's software license is not substituted for the dataset terms. Different document bytes require a new review, even when a supplied rights description says they are allowed. The reviewed hashes are:

Candidate knowledge starts at the original formalization, idea, authorized contexts and complete attempt ancestry. Both source and exposure edges are followed. Compiler-added dependencies do not automatically become prior candidate knowledge; a target already present in the original context is never subtracted. Missing required source/context bindings fail integrity. Opaque exposure annotations remain unresolved and do not support an unseen-history claim. This bounded exploratory path can retain them because known exposure itself is permitted in development exploration.

Protected outcome ancestry and uncontrolled operations ancestry remain explicit scope gaps in this implementation. This is not a contractual ban on all later exploration of released historical results or on registered operational anomalies: those need the separate controlled paths and roles required by the contract and D037. Genuine host-owned implementation packages/certificates are technical provenance, while arbitrary schema strings cannot convert operational observations into technical proof. All ancestry continues to be traversed.

`prepare_evaluation_plan` accepts optional `data_use_assessment_id`. It retains the exact current assessment in its input capsule before child work and rechecks it before commitment. `inspect_evaluation_plan` can satisfy `scientific_data_and_exposure_acceptance` only for that exact development exploration scope; it explicitly returns `protected_target_admission: false`. Historical raw plan gates are unchanged. Legacy requests have no implicit admission. Cancellation retains the original input; revocation or changed/missing evidence reopens the current gate without rewriting historical records.

No market rows are expanded or new outcomes computed by this check, but retained blob hashing can hold the single-writer lock and delay other operator/worker calls. Missing/corrupt evidence produces `DATA_USE_GAP` or a non-current inspection. The operation does not replace outcome eligibility (including partition-crossing labels and `REVIEW_REQUIRED`), semantic review, estimator adequacy, calibration, information targets, protected target binding, atomic allocation/freeze, fixed release, realistic policy costs or deployment authorization.

The [implementation checkpoint](../docs/reviews/implementation-2026-10-25/DATA_USE_INTEGRATION_2026-10-26.md) distinguishes synthetic integration tests, exact real provider-document verification and the existing development probe. None establishes scientific validity or the first genuine multi-model research cycle.
