# Exact composition core

`exact_compositions.ExactCompositionEngine` implements the opt-in scalar `research-ast/4` core under [D097 / bounded-exact-compositions/1.0](../docs/architecture/26_BOUNDED_EXACT_COMPOSITIONS.md). It reuses the existing required-input engine, exact rational types, outward enclosures and fixed budgets. Existing engines and AST1/2/paired AST3 remain unchanged.

The program envelope is exactly `schema`, `catalog_hash`, `expression`. New operators are `integer_power(arg, exponent)`, `trailing_product(arg, bars)`, `trailing_all(arg, bars)` and outcome-only `abs(arg)`. The trusted outcome caller explicitly selects `allow_log=True`; ordinary decision construction cannot use logarithms or absolute values. No new model-controlled capability field is introduced. `describe` retains feature closure and literal/window/exponent parameter paths.

Power/product accept only exact dimensionless ratios. Windows visit every declared slot oldest first, even after false, zero or unknown. Kleene `trailing_all` does not replace the original idea's explicit whole-condition validity guard. Intermediate arithmetic, step/node/depth and integer/window limits are enforced deterministically; no cancellation-based reordering or resource-cap increase is permitted.

The [core qualification record](../docs/reviews/implementation-2026-10-25/exact-compositions-core-2026-11-01.json) separates 24 independent core tests, four complete synthetic engineering-shape tests and 38 existing bounded/required-input tests. The source-approved engineering shape is portable in a test fixture and was compared with a literal original-log oracle, including exact equality, missing/late inputs, original endpoint domains and no signal-close requirement. Tests are scoped software evidence, not a scientific certificate or proof of every possible case.

## Descriptive case and diagnostic library

`exact_outcomes` adds separately versioned `exact-composition-case-request/1`, `exact-composition-cases/1`, `diagnostic-exact-composition-cases/1` and `exact-composition-contrast/1`. This first adapter implements the existing basis-point quantity contrast with `evaluation_contract: required-inputs/1`, `expression_contract: bounded-exact-compositions/1.0` and the existing rigorous numerical contract. Other estimators and scientific admission remain separate. Actual raw outcome features are required; unrelated decision or anchor containers are not.

New complete-window operators contribute their full declared span to outcome lookback, including dependencies whose values are missing. Existing maturity, exclusive-end, publication-cutoff and prior-partition rules remain. Scope-true observed outcomes with false or unknown conditions stay in the whole-scope denominator. Empty conditioned means are undefined; an incomplete base reports `RESOURCE_STOP` without an effect. Numerical zero is an observed value.

Diagnostic replay reconstructs each entire case with the same shared case kernel and compares values, maturity traces, status, exclusion reason, anchor and information interval before reporting that case as checked. The independent review reproduced a defect in the first adapter that accepted altered exclusion status despite unchanged observations; this full-case comparison corrects that new adapter. Existing pinned implementations were preserved. `exact_base_projection` checks the retained base metadata and canonical case-stream hashes. These hashes bind bytes; they do not authenticate a source. `exact_contrast` performs structural validation and arithmetic on supplied reports; owned source authentication and replay against authenticated inputs must still precede native acceptance.

Numerical computation and one diagnostic replay share the original ten-million-step cap. The diagnostic allocation cannot exceed the base request's unused budget. Retain processed prefixes and explicit unprocessed diagnostics after a resource stop. Existing diagnostic event and per-case byte caps remain. The 23 new library tests, 28 exact-core tests and 61 affected legacy tests pass in the [case-layer qualification](../docs/reviews/implementation-2026-10-25/exact-outcomes-2026-11-01.json); 19 new tests were independently authored. This is library conformance, not a native certificate.

A fixed synthetic resource observation completes all 55 declared cases and their diagnostics using 183,536 combined steps. The same engineering shape over the 8,640-coordinate Q1 interval stops after 5,752 base cases at ten million steps, leaving no diagnostic allocation and no aggregate effect. This establishes a resource gap for that shape and synthetic construction, not all equivalent expressions or real-data runtimes. The library enforces the existing cap. Serialized diagnostic streams can exceed one MiB; future native storage must use the existing bounded case-stream mechanism instead of treating a whole stream as one canonical artifact. Encoded size is not measured peak RAM.

**Integration boundary:** versioned native formalization, composition/source certification, owned case-stream storage/replay, full role contract transport and actual research admission have not yet been qualified for AST4. The retained original A still has its original null formalization. These libraries create no H_exec, registry write, model call, grant, empirical outcome or automatic successor. Future use must bind the complete code/contract/profile, preserve independent meaning review and pass actual full-input/resource/accounting checks. Complete original-A execution under the unchanged cap, real model mapping and scientific/economic validity remain unresolved.
