# Exact execution with controlled development feedback

`exact_feedback.ExactFeedbackBroker` is a separate opt-in AST4 broker. It joins the existing exact execution route to the existing paired and second-original controlled feedback imports. The old exact broker directly calls the generic data-use checker, so its original-idea ancestry can contain strictly recognized implementation metadata that is still classified as uncontrolled operations. The old broker also does not inherit the second-original feedback checker. This integration corrects those routing gaps without modifying legacy brokers, package meanings, release criteria, source bytes or stored findings.

The new broker checks its complete source identity and the formalizer's full context through both existing release checkers before obtaining data-use findings. It then invokes the existing second-original import chain, including the paired import chain. Those owners authenticate controller ownership, typed manifest/record/release bindings, epoch and time eligibility, publisher/source identity, retained numerical evidence and dependency usability. Only their existing exact technical-provenance recognizers can reclassify metadata; arbitrary operations, protected ancestry, rights gaps and unresolved exposure remain retained. Nothing is removed from ancestry or exposure. Recognition alone grants no release or data-use permission.

Findings use `exact-development-data-use/2` and bind `exact-controlled-feedback/1`, the exact context and complete installed source identity. This explicit version is incompatible with substituting the new findings into an old frozen compilation capsule. The source inventory includes this adapter, this guide and the second-original publication owner; inherited sources keep their own identity checks. A changed source requires restart and fresh qualification, never refresh of an already loaded closure.

The integration creates no accepted original-A candidate, release, context, worker, epoch, budget grant, provider call or resource-ceiling change. The retained null formalization is not made compilable. Actual current source/release/context membership, independent meaning review, full-wire counting, funding and execution qualification remain required. Tests with scripted provider replies establish software behavior only. The separately pending 20M primitive ceiling remains inactive; current AST4 budgets and mathematical meanings remain unchanged.

Rollback selects the old entry point for future work. Preserve both source versions, all old/new capsules and all original ideas, failures, source/exposure history and charges. Do not reinterpret previously retained findings or reopen consumed grants.
