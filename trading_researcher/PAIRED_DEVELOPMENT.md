# Paired development reference contract

Version: paired-development/1.0, adopted by [D094](../docs/architecture/23_PAIRED_DEVELOPMENT.md). This is an opt-in development calculation, not scientific evidence or a trading policy.

## Expression and candidate syntax

Use `research-ast/3` programs with exactly `schema`, `catalog_hash` and `expression`. The hash binds the full supplied feature catalog. Each feature leaf is exactly `{"op":"feature_at","instrument":"BTCUSDT","ref":"BTCUSDT.close@binance-spot-15m-v1"}` or its exact declared ETH member/reference. All feature reads must be qualified. A selector is a fixed literal, never an expression or dynamic choice. The only permitted pair is `["BTCUSDT","ETHUSDT"]` in that order. Pair order does not choose outcome sign.

Literal, arithmetic, comparison, Kleene Boolean, lag, trailing mean, trailing median and outcome-only `ln` syntax and meanings are unchanged from the supplied bounded-math contract. No new operator for validity, coalescing, conditional branches, null testing or arbitrary code exists. A literal is `{op:"literal",type:"real"|"boolean",unit:string|null,value:decimal-string|boolean|null}`. Preserve exact original validity meaning using supported Boolean expressions. For example `(valid AND predicate) OR ((NOT valid) AND null)` yields unknown for false or unknown validity; plain `valid AND predicate` yields false when valid is false and is not equivalent. Complete guards must inspect all original required samples. Null literal is a Boolean with unit null and value null, not a source observation.

Use `hypothesis-exec/2`, with the same candidate fields as v1: `schema`, `idea_ref`, `claim_kind`, `estimand`, `scope_ast`, `condition_ast`, `outcome`, `comparator`, `horizons`, `test_universe`, `parameter_origins`, `feature_refs`. The **only** universe change is replacing `instruments` with `pair`; retain exact `start`, `end`, `data_snapshot_ref`. Every program uses schema3. `claim_kind` is `difference`, comparator `{kind:"whole_scope"}`, outcome `{program:...,scale:"quantity"}`, horizon `{grid_seconds:900,outcome_bars:positive-integer}`. The estimand contains `kind:"conditional-minus-scope-mean/1"`, `unit:"basis_points"`, `weighting:"equal_rows"`, `missingness:"scope-true-outcome-observed/1"`, `condition_unknown:"exclude-from-condition-retain-in-scope"`, `nuisance_fit:"none"` and the original `direction`.

Parameter origins retain every literal/window/horizon JSON pointer, basis (`preexisting_specification` or `development_observation`), source_refs and rationale. Declare the complete feature_refs closure. Semantic report remains `{status:"equivalent"|"ambiguous"|"different",segments:[{text,path,interpretation}],differences:[...]}`; concatenated segment texts must reproduce the entire original idea exactly, including whitespace. Original source text is authoritative. Do not manually repair or simplify it to fit this syntax. Unsupported meaning requires a null candidate and explicit retained gap.

## Fixed cases, timing and units

One paired case exists for every declared UTC900 timestamp, even with one or both member rows absent. No synthetic composite bar is constructed. Only selected raw feature reads require rows. Literals, lag/window coordinates and unused decision/anchor containers add no market observations. All scheduled dependencies are traced, including false branches and missing inputs. The existing three-valued operators are not replaced with new missingness rules.

Scope and condition use decision time as availability cutoff. The outcome is evaluated at `decision_time + outcome_bars*900`, with cutoff `min(anchor,as_of,exclusive_end-1)`. Each feature uses its own exact timestamp and availability. An anchor at/after exclusive end produces a retained PARTITION_BOUNDARY case. No required read outside the declared universe is available; no prior December or later April rows are added to the original Q1 case. A later publication is not made available merely by a later global as_of.

Canonical raw prices are positive decimal values or missing; volume fields are nonnegative. Contradictory canonical negative/zero prices fail source admission, not silently become valid ratios. The existing source normalizer maps invalid keyed bars to null fields. Original quote-volume-positive and taker-volume-at-most-quote predicates must still be represented faithfully. BTC prices have USDT/BTC units; ETH prices have USDT/ETH units. Their raw difference is invalid. Within-member ratios are dimensionless. Scale a logarithmic-return difference using an explicit `10000` literal with unit `basis_points`.

## Descriptive output and limits

`paired-reference-case-request/1` has the existing request fields with paired universe `{start,end,pair}`. `paired-reference-cases/1` preserves one paired case, all symbol-qualified dependencies and overlapping diagnostic categories per timestamp. Neutral condition_unknown and boundary_censoring categories do not claim invalidity. `paired-case-diagnostics/1` counts true/false/unknown conditions crossed with observed/missing outcomes among scope-true cases. Each category counts a timestamp once even if both symbols are affected.

The whole-scope mean includes observed outcomes with false or unknown conditions; the conditional mean uses only true conditions. Missing outcomes are excluded from both means without dropping their cases. Outcomes overlap and have equal timestamp weights. Bounded logarithm enclosures and rational means produce an outward conditional-minus-whole-scope enclosure. Empty populations stay undefined. Status is descriptive or an explicit gap/resource stop; no confidence interval, significance, protected assessment, scientific support or policy return follows.

The existing limits remain: 256 expression nodes, depth32, 100,000 possible raw rows, ten million total primitive steps and the separately declared 30-minute computation envelope. A case retains at most1,024 unique dependency/diagnostic events. Resource stops retain an incomplete prefix and cannot become a successful result. Owned source snapshots, independent tests, feature certification, meaning review, data-use checks and separate process replay are required before real descriptive execution.
