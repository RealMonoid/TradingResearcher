# Retained historical feedback qualification

The optional `HistoricalFeedbackBroker` in [historical.py](historical.py)
extends `ExactExecutionBrokerV2` for an already released paired/breakout result.
Its D084 envelope was independently reviewed against research-contract/1.0
sections 13/14. Implementation and actual-context qualification must be recorded
separately in the sole work plan; this guide is not an activation certificate.

`qualify_historical_feedback(token, release_ids=[...])` is operator-only and
accepts one through 32 distinct existing releases sharing one original
development snapshot/raw certificate. It accepts no code, paths, expected
results, scientific parameters or status override. RPC uses the same operation
and arguments. Generic source and worker writes cannot mint its namespace.

The existing raw validator executes only the original retained package in a
fresh isolated child on a complete verified private registry/blob copy. All 125
pinned checks and full normalization replay remain required, with the existing
128-file/16-MiB source and 600-second child limits. Every original source byte
must still match its installed counterpart. The full installed raw package is
retained separately as an addition-only currentness seal; its added modules are
not claimed to have executed in the old validator. The adapter source is also
retained exactly. No raw definition or historical object is replaced.

A successful `historical-feedback-qualification/1` is a technical qualification
only. It remains unselected until the caller explicitly passes its ID in the
broker's `historical_qualification_ids`. `historical_feedback_status` checks
that qualification's source/raw binding; its CURRENT refers to the new technical
record, never the old raw certificate and never complete research admission.
The old raw certificate retains its original status, including STALE.

Historical consumption uses a private SQLite read-only/query-only evidence
view with no provider routes, public operations, transaction or blob staging.
It discharges only the installed-package-currency mismatch for the explicitly
bound original certificate/formalization/compiled identities. All existing
release audience, epoch/time, source, data-use/rights/exposure, meaning review,
composition, original-row audit, case replay/bytes and revocation checks still
run. A new compilation, execution or publication uses the unchanged CURRENT
raw-certification gate on the normal broker. This is neither general STALE
acceptance nor a raw-certification override.

Failed attempts retain a gap; interrupted attempts remain in existing bound
computation history. Qualification dependencies participate in the existing
typed technical graph, including direct operator revocation of the new record.
Rollback deselects/revokes it and preserves all records, source bytes, original
results, failures and inherited exposure. The trusted OS account/host Python
remain outside the boundary; the private view is not an OS security sandbox.

No paid call, epoch, retry, slot reset, token exception, source release, protected
assessment, scientific classification, economic claim or capital permission
follows. Current raw certification for new inputs and a finite auxiliary-only
allocation remain separate prerequisites for the actual retained idea.
