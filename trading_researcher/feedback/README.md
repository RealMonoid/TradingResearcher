# Paired development feedback

The opt-in `PairedFeedbackBroker` in [paired.py](paired.py) connects an already qualified fixed BTC/ETH calculation to the existing journal and research-experience views. It is publication and access infrastructure under D070/D078/D094, with no additional scientific meaning, model call, raw-data permission or spending grant. Qualification and actual publication are tracked in the sole implementation plan.

The flow is the original two-perspective discovery cohort, all linked formalization/review attempts and failures, current qualified paired execution, an immutable closed manifest, two typed descriptive records and one atomic later-epoch release. Incomplete, active, protected, revoked or stale inputs stop publication. A null/empty effect remains an information gap; no favorable observation is required.

The adapter statically reuses the reviewed scalar publication structure with separate `paired-development-feedback-manifest/1`, `paired-development-feedback-release/1` and `paired_descriptive_feedback_only` authority. It checks the paired compiler's current embedded data-use assessment, independent meaning assessment, exact composition certificate, complete original-row audit and separate case replay. It does not relabel paired artifacts as scalar artifacts or invent a scalar data-use assessment. Full source ancestry, unknown exposure and both original perspectives remain retained.

Only exact owned paired implementation package/certificate metadata can be classified as technical provenance. Their full ancestry remains traversed; arbitrary operations records and protected inputs still block publication. The package's fixed source footprint and blob linkage are checked. This is a separate administrative classification, not a claim that source code establishes scientific evidence.

All four published objects commit in the native broker transaction. Repeating the identical publication returns its immutable identities; conflicting inputs fail. A release is consumable only after its epoch/time boundary and while its publisher, semantic assessment, numeric/data qualification, case bytes and typed dependencies remain current. The existing context release fallback carries the actual paired grant and exposure. The default broker does not acquire this capability. Descendant contexts inherit the grant checks.

This module is deliberately separate from the unchanged top-level normalizer/evaluator source closure: publication does not implement feature normalization or numeric evaluation. Its own source hash is checked on publication and consumption, and retained in the manifest. Changes to this adapter therefore invalidate its own releases without silently changing the exact numerical certificates frozen in earlier formalizations. Changes to numerical sources still invalidate numerical qualifications normally.

The adapter uses the existing SQLite, content-addressed blobs and memory index. No extra database, service, agent framework or portfolio backend is required. Outputs remain descriptive development feedback; calibration, scientific freeze, protected assessment and economic validation retain their independent prerequisites.

The optional `BreakoutFeedbackBroker` in [breakout.py](breakout.py) extends this
path for the retained second original idea under the existing D084/D094 meaning.
Its separate `paired-breakout-development-feedback-manifest/1`,
`paired-breakout-development-feedback-release/1` and
`paired_breakout_descriptive_feedback_only` authority preserve the installed
first paired publisher and its source identity. The new adapter binds the exact
breakout execution profile, stored meaning/composition identities, retained
execution-input capsule and both replay/audit request hashes. Only exact owned
breakout implementation metadata gains the additional technical classification;
all ancestry remains visible to the existing access checks.

The two typed records explicitly retain the number of conditioned observations
and whole-scope outcomes, distinguish numerical enclosures from statistical
uncertainty, and state that economic usefulness remains unknown. Publication,
explicit later-context retrieval and inherited-grant checks are separate from
new model work. The adapter cannot reopen consumed budgets or turn a single
qualifying case into scientific support. Its tests distinguish isolated metadata
fixtures, genuine retained-result checks on a physical registry copy and the
explicitly simulated inspection of a closed location-bound budget in that copy.
