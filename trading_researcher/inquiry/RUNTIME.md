# Optional inquiry presentation runtime

This separate operator entry point connects the [versioned profile](README.md)
to the exact inline body-table and reference-page representation. It adds no
scientific method, inference allowance or permission to inspect protected data.
The original Broker, BreakoutResearchBroker, worker and their source pins remain
unchanged.

The operator prepares a new base profile with
`source_presentation = presentation.SCHEMA` and the exact
`presentation.TOOLS`, then calls `profiles.build_profile`. An
`InquiryBroker` operator creates the source-bound manifest with
`prepare_inquiry_binding(admin_token, base_profile=..., bundle=...)`.
Pass that manifest as `inquiry_binding` to the existing
`create_research_epoch` operation. The server can reuse
`LocalServer(broker)`; no new network surface or model tool is added.
Only the trusted worker receives the worker capability; the model does not
receive the operator credential or arbitrary shell/filesystem/network access.

The epoch stores the actual profile, base/profile provenance and installed
source closure. Both perspectives use the same frozen context and stay private
until normal completed-batch release. The nine explicit tools retain authorized
full source reads, bounded scalar/paired/ancestry pages and ordinary records.
IDs returned in a page do not grant access to those IDs.

## Visible and retained inputs

`worker.run_research_once(client, provider, cancel=None)` uses three initial
messages: the exact frozen system prompt, a small explicit transport notice, and
the complete canonical inline body-table packet from authorized context roots.
Every unique original retained body is initially inline; memberships, sources
and exposure remain at each occurrence. Deferred pages contain only their
specified reference lists. The caller cannot replace the packet or notice by a
summary, omit a source or change its order.

Every successor request must match the previous retained request, actual
provider response, complete ordered tool results, and any required visible
measurement view. Missing, changed or reordered records deny a successor call.
Terminal responses permit no further call, and transport retries remain within
the existing allowance. Exact repeated dispatch keys retain native idempotency.
No provider-side rewrite or runtime code generation is used. The installed
source files are ordinary static Python; their one-time construction from
inspected legacy methods is retained in the dated construction record.

The controller checks the retained trajectory and trusted installed worker
path. This is not remote attestation against a malicious operator, OS or
replacement worker. Valid record order and hashes do not establish that a tool
interpretation, diagnosis or next action is good. A reread can repeat information
already present in the initial context; it does not prove purpose before first
exposure. Applicable model-produced AC/DQ checks remain separate.

## Currentness, accounting and limits

Source identity includes the installed package Python inventory, governing
contracts and inherited paired closure. Added, removed, changed or unreadable
sources deny dependent admission, access, reservation or completion. There is
no silent refresh of a frozen epoch.

If sources change during a dispatched call, settlement authenticates and
retains its actual response and accounting first. The same successful
transaction persists a source-currentness flag and halts the epoch. The worker
then blocks without using that response as an accepted research result.
Currentness denial does not erase a bill, pretend usage is unknown when known,
or convert a technical failure into market evidence. Repeat settlement returns
the recorded receipt. Cancellation, late receipts and stale capabilities retain
their inherited rules.

InquiryBroker retains ordinary 80,000-token, 12-call and 1,800-second ceilings
and denies all legacy budget overlays and review continuations. A finite
disposition is available only through the separate FiniteInquiryBroker in
resource_host.py and its [explicit resource contract](RESOURCES.md). No old
allowance is reusable. That contract permits conditional four-stage funding;
it does not guarantee an arbitrary full future packet will fit the cash cap.

For this separate entry point, the operator prepares the actual enlarged base
profile before calling profiles.build_profile, binds the new complete installed
closure with prepare_inquiry_binding, and freezes both complete downstream
profiles and two distinct discovery provider run IDs with
prepare_resource_disposition(admin_token, role_profiles=...,
discovery_run_ids=...). Pass that result as resource_disposition to
create_research_epoch. This creates one external, nonrenewable resource fence;
installation alone creates none. The trusted CountedOpenAIResponsesProvider
for each discovery must use its prebound run_id, epoch_id and worker identity.
The worker blocks a successor count or call after that perspective's one slot.

Use the native auxiliary worker with provider=None for formalization/review.
The finite controller chooses its exact configuration from the frozen role,
while credential and shared-ledger locations come from the installed provider
route. It counts the entire actual packet outside the registry transaction,
then rechecks access, lease, source, stage, configuration and packet currentness
before reservation. Durable shared-ledger receipts must authenticate against
the native call and exact wire before unspent inference reservation can be
released. Missing, stale or mismatched accounting retains the response and
commits a halt. The actual model review remains an independent scientific role;
the resource checker does not decide meaning or empirical success.

Model-produced behavior, semantic qualification of actual role prompts, actual
full future wire counts under this new source/configuration closure, funded
native admission and scientific/economic usefulness are not established by
scripted route checks. Older wire counts remain historical observations and
cannot attest the new closure. No paid call or production registry change
follows from installing these modules. Count-service billing remains unknown
and is separate from inference-ledger arithmetic.

Count attempts retain their complete request, requested model identity and UTC
before external work. The auxiliary controller retains observed or failed
count results in a separate transaction even when later native admission is
denied, and halts a failed attempt. These operational records grant no inference
or scientific authority. Finite discovery writes its start/observation through
its existing worker capability. If that lease expires during counting, the
durable start remains unresolved; the worker returns a non-accepted
reconciliation result carrying its count receipts. The operator must persist
that returned result. This is no claim that a stale worker can write the later
observation, or that crash-proof count-service billing has been established.

For a future profile that selects the already adopted scalar bounded-math reuse,
both auxiliary role configurations must explicitly choose the same exact
bounded_math_scope. The existing adapter supplies the complete pinned document
20 to both actual wires; the finite broker also supplies the complete pinned
mathematical document 18 before a scalar candidate exists. Both documents are
part of the installed source binding. Unselected profiles retain their earlier
packets, and paired packets retain their complete native documents. These
supplements change no mathematical meaning or activation scope. Historical
original-idea examples and consumed first-run budgets do not replace a newly
submitted original idea or create a new grant. Every actual full wire must be
counted with its selected supplements; old counts attest no changed wire.
